# WSJT-Fusion 1.0.0-beta3 — macOS Apple Silicon

This beta introduces the WSJT-X 3.3.0-beta2 decoder reference while retaining
Fusion's own operating interface, filters and automation. FT2 continues to use
its separately tracked WS/Improved 3.2.1 build 261010 receiver.

## Decoders and maintenance boundary

The exact WSJT-X reference is `9d059511f77e2d1be746ebfeaa7f88e77c1babb7`.
Standard timed modes use a separately built upstream engine behind an explicit
Fusion IPC/parameter adapter. MSK144, FreqCal and Echo use narrow ABI adapters;
WSPR uses the upstream worker. The source archive, hashes, credits and build
procedure are retained under `wsjtz/decoding/wsjtx-beta2/`.

The beta2 JTTY correction rejects unencodable segments rather than retrying
shorter pieces. Other JTTY codec files unchanged between the upstream betas
retain their original exact provenance.

The public Fusion beta2 tag and assets remain untouched for rollback. No
unrequested upstream UI changes are imported. Future upstream UI/ergonomics
changes must be reported for F6FDY's explicit selection.

## Fusion changes

- JTTY single-click selects/highlights the correspondent; double-click sends
  F2 in FT8 message style. This action transmits when the radio is configured.
- Independent all-band and Rx ± F Tol histories, with local transmissions.
- RX/TX waterfall goal posts, TX frequency hold, consistent Pwr meter width.
- Enable Tx is red during JTTY transmission; timed progress is hidden in JTTY.
- Colors cover printed text only. TX receives one uniform configured color.
  Received-line colors are based on the identifiable sender (DE/CQ/call-call),
  not the destination. Partial or unidentified senders are not highlighted.
- Strict FIFO after the initial priority-based station choice; repeated calls
  neither duplicate a queue entry nor move it.

## Validation and limits

22 Fusion regression suites passed before the FIFO refinement; the queue tests
were rerun for that refinement. Tests cover the real shared-memory FT8 classic,
FT8 multithread and FT4 adapter, JTTY encode/receive loopback and segment refusal,
receive history, sender/color boundaries, FT2 and automation. The packaged
worker was also exercised with synthetic FT8/FT4 audio.

11 upstream engine/spectrum/Echo tests passed, including synthetic preparation.
No tests transmit RF or open the operator's audio devices. This is a test beta:
live radio operation and weak-signal comparisons still need operator validation.

The macOS application is locally ad-hoc signed, not Apple-notarized. Only the
macOS Apple Silicon build is validated here; no Windows binary is provided.

## JTTY manual report correction
%R uses the rounded arithmetic mean in dB from the first three distinct messages
of the selected correspondent (one or two until three are available). The
selected line seeds the first measurement. Progressive updates replace their
own measurement; the fourth message does not change the sample set.
RSTS is taken from the actual outgoing report text, not from a stale timed-mode
report or a later instantaneous receive SNR. CQ/locator messages do not invent
a sent report. Received-report inference and automatic logging remain deferred.

### Live macro previews and logger mode

The JTTY macro panel shows the expanded transmit text below each editable template, in smaller text directly on the panel background. Previews update immediately when selecting a correspondent or changing callsign, grid, report, serial number, next call or template. Sending and previewing share the same expansion function. The two macro groups have additional vertical spacing; Call next and Serial Number share a row. These are Fusion interface changes.

Manual JTTY QSO logging explicitly supplies `JTTY` to the common logging dialog, so ADIF and UDP QSO notifications carry the same mode for every connected logger, independently of the macro message style.

JTTY colours check countries, other entities and overall calls across modes. Only the call-on-band check requires a JTTY contact: a station previously worked on the band in FT8/FT4 is highlighted as New call on band, without reclassifying its country as new. Other modes retain their existing highlight setting.
