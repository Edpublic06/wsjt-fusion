# FT2 from WS / Improved

Source: WS 3.2.1, build 261010, Uwe Risse DG2YCB and collaborators;
WSJT Development Group. GPL-3.0-or-later. See the root NOTICE.md and COPYING.

`source-manifest.json` records the archive checksum, original file hashes and
symbol mapping. Files under `upstream/` are derived from those sources with
private symbol names and local parameter includes; modification dates appear
in their headers. Their algorithmic content is preserved.

This receiver is private to FT2. The standard FT4 and existing Z FT8 paths
continue using their own implementations. The application adapts 12 kHz FT2
PCM to the FT4 time domain by repeating samples, supplies the 3.75 s sequence
period, and converts frequency and DT back in `lib/decoder.f90`.

Changes include the 23-half-symbol capture window, updated metric/candidate
passes, A7 history, the period-aware receiver interface and the -0.25 s DT
correction. Existing Z filtering, automation and the FT2 transmitter remain.

## Validation, 13 October 2026

- macOS arm64 Release build: `jt9`, `wsjtx`, `ft4sim` succeeded with the
  existing Homebrew dependencies, without updating them.
- `wsjtz_ft2_regression` passed: signals generated by the existing FT4
  transmitter, compressed to FT2 timing, decoded at depths 1/2/3, at nominal
  and late arrival times, with frequency and DT checks and no duplicate
  message; original FT4 decoding was also checked.
- Real radio, CAT/PTT and live audio checks are still outstanding.

To reproduce the regression, configure with `WSJT_BUILD_UTILS=ON`, build
`wsjtz_ft2_regression`, and run that executable from the build directory.
This is synthetic-signal validation, not a measured sensitivity comparison.

For an update, compare only this private receiver against the next WS source
reference, maintain the symbol map and manifest, and rerun the receiver and
application tests before publishing a binary.
